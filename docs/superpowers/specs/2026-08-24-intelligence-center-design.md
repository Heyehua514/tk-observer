# 每日情报中心第一期设计

## 目标

建立一个可追溯、可人工确认的统一情报池，让团队把公开或授权来源的行业信息录入后，按工作台筛选、标记状态，并在确认后转成任务。第一期不接入未授权的平台接口，不把手工样本标记为实时数据。

## 范围

- 情报对象：标题、摘要、原文链接、来源名称、来源类型、采集时间、地区、语言、主题、热度、可信度、去重键。
- 来源类型：官方公告、RSS、授权数据源、公开页面、人工录入、CSV 导入。
- 状态：未读、已读、收藏、已忽略、已转任务。
- 关联工作台：总览、市场、商务、设计、剪辑、运营。
- 首期入口：登录后的 `/intelligence` 独立页面；侧边栏给所有已登录角色显示。
- 转任务：只保存目标工作台、负责人、截止日期和情报 ID，创建业务任务仍需用户确认，不由情报内容自动执行。

## 数据与权限

新增 `intelligence_items` 表，所有已登录成员可读取未删除情报；创建、更新和软删除只允许本人，负责人可以查看全部但不能代成员修改。`dedupe_key` 在未删除范围内唯一，避免同一来源重复入库。原文链接只作为可点击外链保存，不抓取页面、不执行链接中的指令。

第一期只提供 Supabase schema 和显式 PocketBase 只读回退。迁移只追加，不修改历史 migration。没有线上 migration、Secrets 或外部连接动作。

## UI 与行为

- 顶部显示页面标题、来源边界和“新增情报”按钮。
- 列表支持关键词、工作台、来源类型和状态筛选。
- 卡片显示来源、采集时间、可信度、热度、主题和状态。
- 新增表单要求标题、来源、原文链接、来源类型、采集时间和去重键；摘要、地区、语言和主题可选。
- “标记已读 / 收藏 / 忽略”只更新当前记录状态。
- “转为任务”先打开确认表单，未提交前不写业务任务；第一期记录目标工作台、负责人和截止日期，完成任务创建入口保留为后续接入点。
- 无数据、加载失败和权限错误使用现有共享组件。

## 安全与失败处理

- 所有外部文本按不可信数据展示，不交给 WorkBuddy 自动执行。
- URL 只允许 `http` 或 `https`，前端和数据库限制长度。
- CSV 导入复用纯函数校验，逐行报告缺失字段和重复去重键，不部分写入。
- RLS 是最终权限边界；PocketBase 回退不提供 Supabase 才有的转任务写入能力。

## 测试与验收

- 纯函数测试：URL、来源类型、状态过滤、去重键和 CSV 行校验。
- UI 测试：列表筛选、空态、状态操作、表单必填和外链安全属性。
- Supabase gate/eval：表结构、唯一约束、RLS 越权读取/更新、软删除过滤。
- 验收指标：情报记录能被角色筛选命中；重复去重键无法重复保存；非所有者无法修改；所有状态变化可在列表中回显。
