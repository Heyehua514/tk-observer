# 工作台每日情报中心设计

## 目标

每日情报中心将外部变化整理成各工作台可以执行的事项。它不是市场工作台的附属页面，而是工作台级统一情报池：同一条情报只采集和归档一次，再按工作台、角色、地区和主题分发。

第一期目标不是追求来源数量，而是保证每条内容可追溯、可去重、可判断可信度，并能从情报转成收藏、讨论或任务。

## 用户和入口

| 用户入口 | 默认内容 |
|---|---|
| 总览首屏 | 今日重点、风险、需要负责人处理的情报 |
| 独立情报中心 | 全部情报、筛选、搜索、收藏、已读和转任务 |
| 市场工作台 | 流量话题、类目趋势、竞品和活动动态 |
| 商务工作台 | 客户行业、品牌合作、商机相关事件 |
| 设计工作台 | 视觉风格、广告素材、包装和商品呈现趋势 |
| 剪辑工作台 | 选题、音乐、标签、视频结构和内容趋势 |
| 运营视图 | 平台规则、活动、物流、履约和风险 |

同一用户可以切换“全部情报”和“当前工作台情报”。角色权限仍由服务端控制，情报分类不能绕过原有业务权限。

## 情报对象

第一期的统一情报对象至少包含：

| 字段 | 说明 |
|---|---|
| `id` | 情报唯一 ID |
| `title` | 原始或归一化标题 |
| `summary` | 事实摘要，不混入未经标注的推测 |
| `source_name` | 来源名称 |
| `source_type` | 官方公告、RSS、授权数据源、公开页面、人工录入、CSV 导入 |
| `source_url` | 原始来源地址 |
| `published_at` | 来源发布时间，未知时为空 |
| `collected_at` | 系统采集时间 |
| `region` | 国家或地区 |
| `language` | 原文语言 |
| `topics` | 主题标签，如流量、竞品、规则、物流 |
| `workspaces` | 关联工作台集合 |
| `heat_score` | 来源数据或人工确认后的热度分数 |
| `confidence` | 可信度：高、中、低 |
| `dedupe_key` | 来源、标题、日期和规范化链接组成的去重键 |
| `status` | 未读、已读、收藏、已忽略、已转任务 |
| `action_hint` | 可执行建议，必须与事实摘要分开显示 |
| `raw_payload` | 受权限保护的原始来源数据，前端不直接展示敏感字段 |

## 来源边界

允许接入：

- 平台官方公告和规则页面。
- 有明确授权的 API 或数据服务。
- 合法公开 RSS、公开页面和可追溯的公开数据。
- 人工录入和 CSV 导入。

暂不承诺：

- 没有公开 API 或授权依据的 TikTok、微信后台自动抓取。
- 需要登录绕过、验证码绕过或违反平台规则的采集。
- 只凭模型生成、没有来源链接的“新闻”。

对于人工或模型整理内容，必须保留原始来源和操作者。没有来源的内容只能标记为“内部建议”，不能标记为外部新闻或高可信情报。

## 处理链路

```text
来源适配器
  -> 原始记录保存
  -> 链接和标题规范化
  -> dedupe_key 去重
  -> 主题与工作台分类
  -> 热度、可信度和地区标注
  -> 摘要与行动建议
  -> 总览和工作台分发
  -> 已读/收藏/忽略/转任务
```

去重必须在数据层或稳定服务层完成，不能只依赖前端标题比较。重复运行同一来源不会重复生成情报或任务。

## 前端结构

### 总览摘要

- 显示 3 到 5 条今日重点。
- 每条显示来源、时间、关联工作台和可信度。
- 支持“查看全部”和“转为任务”。
- 高风险规则或履约事项需要明确风险标记。

### 独立情报中心

- 顶部搜索、时间范围、地区、来源、主题和工作台筛选。
- 使用客户端锚点导航定位“今日重点、趋势变化、风险提醒、已收藏”。
- 情报列表按日期分组，未读项保留视觉层级。
- 详情使用右侧抽屉：事实摘要、来源、相关工作台、行动建议、关联任务。
- 移动端使用汉堡菜单和全宽 Sheet 抽屉。
- 有层级筛选时使用 Cascader；日期和日期范围使用 DatePicker。

### 工作台嵌入卡片

- 只显示与当前工作台相关的情报。
- 支持收藏、已读和转任务。
- 不在各工作台重复实现采集、去重和来源管理。

## 转任务规则

转任务时至少需要：

- 目标工作台。
- 负责人。
- 任务标题。
- 截止时间。
- 来源情报 ID。
- 原始链接。

转任务后，任务详情仍显示情报来源。情报被删除或标记忽略时，已经创建的任务不自动删除，只保留来源失效提示。

## 质量指标

第一期需要记录：

- 来源抓取成功率。
- 来源延迟。
- 去重率。
- 解析失败率。
- 低可信内容占比。
- 情报被阅读比例。
- 情报被收藏比例。
- 情报转任务比例。
- 转任务后的完成率。

这些指标用于判断情报是否真正减少信息搜集成本，不以每天生成多少条内容作为唯一成功标准。

## 分阶段实施

### 第一期：统一情报池和前端入口

- 完成类型、状态、来源、主题和工作台契约。
- 用人工录入或 CSV 导入验证列表、筛选、详情、收藏、已读和转任务。
- 总览和各工作台只读消费统一情报对象。

### 第二期：接入低风险来源

- 先接官方公告、RSS 和已授权数据服务。
- 每个来源单独记录健康状态和失败原因。
- 增加定时任务，但保留手动重试和人工导入。

### 第三期：摘要和行动建议

- 使用项目允许的本地 WorkBuddy/CodeBuddy 链路生成摘要和建议。
- 事实摘要、模型建议和人工结论分开存储和展示。
- 模型失败时保留原始情报，不阻塞来源入库。

## 验收标准

- 同一情报在总览、市场和剪辑工作台只出现一个统一记录。
- 每条情报都有来源、时间、可信度和去重键。
- 点击情报可打开详情抽屉并回到原工作台上下文。
- 情报可以转成带来源的任务。
- 移动端没有横向溢出，抽屉内容可滚动，保存操作可见。
- 重复同步不会重复创建情报或任务。
- 来源不可用时显示失败状态，不生成无来源的假新闻。
