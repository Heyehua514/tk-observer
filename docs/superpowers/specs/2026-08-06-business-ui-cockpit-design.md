# 商务工作台 UI 驾驶舱设计规格

## 目标

在不修改业务逻辑和 PocketBase 数据模型的前提下，把商务工作台从静态数据页升级为可执行的运营驾驶舱。

用户进入页面后，应能在首屏完成五件事：判断经营状态、识别重点商机、查看近期动作、进入业务处理、回看执行结果。

核心闭环：

`目标 -> 当前进度 -> 待处理动作 -> 执行结果 -> 数据复盘`

## 本轮范围

- 商务工作台首页的信息架构与视觉层级。
- 全局共享的页面过渡、数字动画、角色头像、指标卡、空状态、表格样式、通知动画、Toast 和北京时间。
- 商机 Pipeline 卡片的拖拽反馈。
- 已有 Recharts 图表的入场动画。
- 加载、空数据、错误和减少动态效果状态。

本轮不修改：

- PocketBase collections、migration 和 hooks 数据契约。
- 客户、商机、商单、朋友圈计划的业务规则。
- 权限、路由与登录流程。
- 市场、设计、剪辑和老板工作台的页面结构。共享组件可供后续复用，但本轮不主动重构这些 feature。

## 首屏结构

### 顶部状态区

- 保留登录后动态问候：按北京时间显示早上好、中午好或晚上好。
- 问候从顶部下落，带轻微缩放和回弹，约 3.5 秒后淡出，每次登录只播放一次。
- 顶栏显示当前北京时间，按分钟刷新。
- 通知铃铛仅在出现新未读消息时摇晃一次。
- 右上角统一使用角色色块头像。

### 第一层：经营状态

- 展示总客户数、本月新增客户、进行中商机、预计成交金额、本月商单数。
- 数字首次进入或值发生变化时，从 0 计数到真实值，持续 0.6 秒。
- 趋势只展示真实可计算的对比数据。缺少上期数据时显示“暂无对比”，禁止写死百分比。
- 指标卡可点击时必须进入对应筛选结果；不可点击时不使用按钮视觉。

### 第二层：核心驾驶区

- 左侧约 60% 宽度为大尺寸商机 Pipeline，作为首屏视觉焦点。
- 各阶段展示数量、金额与商机卡片，卡片包含客户、商机名、金额、概率和预计成交日。
- 拖拽时卡片 `scale(1.02)` 并增强阴影，落下后恢复。
- 阶段列根据现有枚举生成，后续增加阶段时无需重写页面结构。
- 右侧为行动队列，按优先级展示即将超期、待跟进、最新成交和招商提醒。
- 行动项必须有明确入口，禁止只展示不可处理的提示。

### 第三层：执行结果

- 最近渠道商单：展示状态、金额、客户和发布日期。
- 本周朋友圈计划：展示计划、发布与复盘状态。
- 最近客户动态：展示新增客户、商机阶段变化和成交结果。
- 各区块保持信息密度，不使用装饰性嵌套卡片。

## 动效规则

- 页面切换：淡入并上移 6-8px，持续 0.2 秒。
- 指标数字：0.6 秒，缓出，不反复播放。
- 表格行：背景轻微变亮并 `scale(1.005)`，不得导致列宽或容器抖动。
- 通知铃铛：新未读消息到达时旋转约 15 度，共三次，不循环。
- 看板拖拽：`scale(1.02)` 加阴影。
- Recharts：`animationDuration=800`，折线从左向右绘制。
- 系统开启 `prefers-reduced-motion` 时，关闭位移、摇晃和计数过程，直接显示最终状态。

动画只解释状态变化或提供操作反馈，不添加循环背景、漂浮光球和无业务意义的运动。

## 视觉规范

### 角色头像

统一为 34px 方形、8px 圆角、白色 14px 粗体文字，取姓名后两个字：

| 角色 | 颜色 |
| --- | --- |
| 磊哥 | `#3B82F6` |
| 雨辰 | `#8B5CF6` |
| 素云 | `#10B981` |
| 铭泽 | `#F59E0B` |
| 谢洁 | `#EC4899` |

头像组件用于顶栏、任务分配、活动动态和业务动态，不允许各页面自行定义颜色。

### 表格

- 使用极淡斑马纹，避免大面积灰色。
- 中文表头使用 12px、中等字重和适度字距；仅英文缩写使用大写。
- hover 反馈不得改变行高和列宽。
- 状态标签沿用现有语义色，不增加新的同义颜色。

### 空状态

- 使用轻线条图形、具体原因和一个明确动作。
- 示例：“还没有商机，创建第一条商机开始跟进”。
- 禁止只显示“暂无数据”。
- 图形采用共享组件或现有图标组合，不引入大体积插画依赖。

### Toast

- 使用现有 shadcn 体系中的 Sonner，从顶部进入。
- 成功、警告、失败使用克制的语义色和统一圆角。
- Toast 文案说明结果和下一步，不重复页面上已明确的信息。

## 数据与状态边界

- 所有指标、趋势和 Pipeline 数据继续使用现有 hooks。
- 趋势数据只有在存在可验证的当前周期与上一周期时才展示百分比。
- 行动队列由现有商机截止日期、阶段和状态派生，不新建后端字段。
- 派生计算应写成纯函数并带单元测试，避免在组件 JSX 中堆叠业务判断。
- 空数据、部分数据加载失败和权限不足必须独立处理，不能让整个驾驶舱白屏。

## 组件边界

共享组件仅放在现有 shared 组件目录中：

- `RoleAvatar`
- `AnimatedNumber`
- `MetricCard`
- `GuidedEmptyState`
- `PageTransition`
- `BeijingClock`

商务工作台专属组件保留在 `features/business/` 内：

- 驾驶舱布局
- Pipeline 主视图
- 行动队列
- 最近业务结果区

不创建通用“万能卡片”，不移动其他 feature 的业务组件。

## 验收标准

1. 商务工作台首屏清楚呈现经营状态、Pipeline、行动队列和执行结果。
2. 所有指标来自真实数据，趋势缺少比较基准时不伪造百分比。
3. 页面、数字、表格、铃铛、拖拽和图表动画符合统一时长与触发规则。
4. 开启减少动态效果后，页面仍可完整操作且无持续动画。
5. 头像在顶栏和商务动态区域保持相同尺寸、文字与角色颜色。
6. 空数据、加载失败和部分数据缺失时有明确状态，不出现白屏。
7. 不修改 PocketBase migration、数据表和业务规则。
8. 新增纯函数与共享组件具备 gate tests；关键驾驶舱流程具备 eval/交互测试。
9. `pnpm typecheck`、`pnpm lint`、测试和生产构建全部通过。
10. 桌面与移动视口均无文本溢出、布局跳动和控件重叠。

## 可见结果

- 用户从进入商务工作台到打开重点商机的路径不超过两次点击。
- 首屏直接暴露临期任务和高价值商机，不需要先进入列表筛选。
- 动效只在进入、数据变化、新通知和拖拽时发生，不干扰连续办公。
