# 部署与多端说明

> 适用版本：Supabase-first（默认数据源）+ PocketBase 显式回退。
> 更新日期：2026-08-13。

## 当前架构

- 前端：Vite + React 18 SPA（`apps/web`）+ Tauri 2 桌面壳（`apps/desktop`）。
- 数据层：默认 Supabase（`src/lib/data-provider.ts` 未配置时默认 `supabase`）。Auth、业务表、RLS、Storage、Realtime、pg_cron 自动化全部由 Supabase 承担。
- 回退：设置 `VITE_DATA_PROVIDER=pocketbase` 时切回 PocketBase，本地联调仍可用。**PocketBase 已冻结（2026-08-14）**：15 个已发布 migration 与 hooks 仅作只读回退，不再追加业务功能；新增能力一律走 Supabase migration（校验：`node scripts/supabase/pocketbase-freeze-check.mjs`）。
- 同步策略：桌面、Web、手机共用同一个 Supabase 项目，多端天然实时同步；无独立自建后端。

## 本地开发

```bash
pnpm install
pnpm supabase:start        # 本地 Supabase（Docker）
pnpm supabase:reset && pnpm supabase:test && pnpm supabase:types
pnpm dev                   # Web 前端（默认连本地 Supabase）
pnpm desktop:dev           # Tauri 桌面壳
```

前端环境变量（`apps/web/.env`，已被 git 忽略）：

```dotenv
VITE_DATA_PROVIDER=supabase
VITE_SUPABASE_URL=http://127.0.0.1:54321
VITE_SUPABASE_ANON_KEY=<local-anon-key>
```

PocketBase 回退联调时改为 `VITE_DATA_PROVIDER=pocketbase` 并配置 `VITE_POCKETBASE_URL`。

## 远程部署（推荐路径）

1. **Supabase 生产项目**：`supabase login` → `supabase link --project-ref <ref>` → `supabase db push` 应用全部 migration → `supabase gen types typescript` 同步类型。RLS 已在 migration 内配置，生产无需手动授权业务表。
2. **Web 静态托管**：Vercel / Netlify / Cloudflare Pages 任一，构建命令 `pnpm --dir apps/web build`，环境变量填生产 Supabase URL 与 anon key（anon key 可进浏览器，权限由 RLS 控制）。
3. **桌面端**：Tauri 壳使用同一份前端构建；打包时把 `VITE_SUPABASE_URL` 指向生产项目，`pnpm desktop:build -- --bundles dmg`（macOS）或 Windows 上 `--bundles nsis`。
4. **手机端**：Web 托管地址手机浏览器直接访问即可；后续可加 PWA manifest 支持“添加到主屏幕”，不依赖应用商店。Supabase 数据与文件存储天然支持手机端读写。
5. **文件上传**：场地照片、物料、设计稿、成片走 Supabase Storage 私有 bucket（已有 `video-files` 等配置），桌面与手机共用同一 bucket，URL 权限由 RLS / storage policy 控制。
6. **远程维护账号**：不开放公开注册（现有注册白名单只用于本地五人）。远程维护账号在 Supabase Auth 后台创建，角色写入 `profiles`；设置页保留 PocketBase 回退服务器配置项。

## 成本参考（高层级，以官方页面为准）

- Supabase Free：适合开发与验收；Pro 约 $25/月，含数据库、Storage 与带宽基础额度。
- PocketBase 自托管：服务器费用 + 维护成本；当前仅作回退，不承担线上主数据。
- 域名：另计，非必需（可用平台默认域名）。

## 数据迁移（已就绪）

- 对账：`node scripts/supabase/reconcile-pb-export.mjs`（只读对比 `backend/pb_data/data.db` 与 `supabase/migrations`）。
- 导出：`node scripts/supabase/export-pb-business.mjs`（已映射业务表导出 JSON + CSV 到 `/tmp/tk-observer-supabase/`）。
- 当前状态：44 张 PB 表 vs 39 张 Supabase 表；12 张映射表 21 行业务数据待导入；唯一列缺口 `event_materials.designer` 已由 `20260813001000` 收口。`users` 不迁移为业务表，由 Supabase Auth + `profiles` 承接。
- 文件（图片/视频）迁移到 Supabase Storage 与真实数据导入属上线前动作，需要 Supabase 运行环境，按红线留到部署阶段执行。

## 上线前安全检查

- 不提交密钥：service role key 只允许服务端使用，禁止进入 `VITE_*`、仓库、日志或截图。
- 公网部署前关闭公开注册：远程新增成员通过受控邀请或后台创建。
- 邮箱枚举提示：`account_exists.pb.js` 仅适用于受控内部网络；公网开放前加网关限流、IP 白名单或统一认证错误。

## 上线前自检

```bash
node scripts/supabase/deploy-check.mjs
```

只读检查前端环境变量（存在性与是否误配高权限密钥，不打印值）、migration 时间戳顺序与关键文档完整性，并输出部署建议顺序。硬性失败退出码 1，警告不阻断。对应测试：`node --test scripts/supabase/deploy-check.test.mjs`。
