>
> 盘点日期：2026-08-21
>
> 状态说明：
> - **已落地**：代码、测试或自动化验收已有证据。
> - **部分落地**：页面或数据模型已存在，但真实数据、跨模块链路或线上环境仍未闭环。
> - **待建设**：PRD 已定义，但当前仍是骨架、占位或缺少核心实现。

## 一、产品定位

TK观察工作台是面向 TikTok Shop 跨境电商团队的内部多角色协作系统，目标是把负责人、商务、市场、设计和剪辑的日常工作集中到一个入口，减少表格、聊天记录和本地文件之间的信息割裂。

系统目前采用：

- Web：Vite + React + TypeScript + TanStack Router/Query/Table + shadcn/ui + Tailwind CSS。
- 数据：Supabase Auth、Postgres、RLS、Storage、Realtime、自动化；PocketBase 作为显式回退。
- 桌面端：Tauri 2。
- 数据真实性原则：没有公开 API 的平台数据不伪装成自动抓取，使用人工录入、CSV 导入或后续外部数据适配器。

## 二、用户与工作台

| 角色 | 默认入口 | 主要职责 |
|---|---|---|
| boss | 总览工作台 | 经营总览、审批、团队进度、活动监督、通知 |
| business | 商务工作台 | 客户、达人、商机、商单、朋友圈、活动招商 |
| market | 市场工作台 | 活动、场地、报名、招商、物料、财务复盘 |
| design | 设计工作台 | 素材上传、审批、设计需求、设计任务、交付 |
| editing | 剪辑工作台 | 选题、视频调研、对标账号、热点、风格分析 |
| business 测试成员 | 商务工作台 | 本地流程和权限测试 |

权限由三层共同组成：前端路由守卫、Supabase/PocketBase 服务端规则、业务触发器或约束。前端不能作为最终安全边界。

## 三、已具备的全局能力

### 已落地

- 邮箱密码登录和成员注册。
- 登录后按角色进入默认工作台。
- 全局搜索，按达人、商品、视频、客户等分组，并按角色隐藏无权限数据。
- 工作台级搜索、组合筛选、排序和部分 URL query 同步。
- 通知铃铛、未读数、单条已读、全部已读和通知列表筛选。
- Supabase Realtime 或 PocketBase realtime 的相关查询失效刷新。
- 团队日历，聚合活动、活动任务、设计需求、朋友圈计划和渠道商单排期。
- PWA manifest、Service Worker、离线登录壳和移动端侧栏抽屉。
- 统一错误态、加载骨架、空状态、Toast、北京时间和角色头像。
- 液态玻璃视觉系统、深空背景、响应式布局、减少动态效果支持。
- 团队记忆自动化：日报、周报、截止提醒、失败案例、审计流水。
- 本地 WorkBuddy/CodeBuddy AI 分析链路，异步写回内容分析结果，不阻塞录入。

### 部分落地

- 飞书 OAuth 与同步函数已有本地合同、类型检查和 fail-closed 校验，但正式凭据、HTTPS 回调、Secrets 和远程部署仍未完成。
- 远程 Supabase 项目和成员账号已建立，但正式成员策略、公开注册关闭、真实数据导入和上线验收仍需要人工确认。
- 文件迁移脚本和 Storage 权限抽样已完成，但仍需正式环境持续验证和缩略图策略确认。

## 四、总览工作台

### 已具备功能

- GMV、签约达人、待办任务、出片数、团队动态、成员任务进度。
- 今日简报、本月失败案例、本周自动化运行指标。
- 审批入口、通知入口、团队日历入口。
- GMV 录入和人民币口径展示。
- 指标数字入场、趋势图、团队动态和玻璃化视觉层。
- 页面锚点导航，支持在长页面内快速定位核心指标、走势和运营状态。

### 仍需完善

- 经营指标按时间、站点、币种和业务范围筛选。
- 汇率口径和多币种统一规则。
- 更完整的管理图表和经营异常解释。
- 将每日情报摘要、风险提醒和跨工作台待办放到总览首屏。

## 五、商务工作台

### 达人管理

- 新增、详情、编辑、删除、搜索、筛选、排序、分页。
- 批量状态更新和批量删除。
- 达人详情关联视频。
- 可商务合作标记、合作报价和商务备注。
- 商单表单只展示 `is_biz_available=true` 的达人。

### 公司与客户

- 公司/供应商名录。
- 客户 CRUD。
- 联系人、电话、微信、行业、来源、重要度和备注。
- 行业、来源、重要度筛选与名称/对接人搜索。
- 客户详情基础信息、关联商机和关联商单。
- 关联商机可直达商机页，关联商单可直达并高亮定位。

### 商机 Pipeline

- 六阶段：初步接洽、方案报价、商务谈判、合同签署、已成交、已流失。
- 拖拽流转、阶段概率自动维护。
- 已流失必须填写原因。
- 预计金额、预计成交日、跟进备注。
- 截止提醒、成交通知、状态历史、失败案例沉淀。
- 当前最新优化：商机详情已改为响应式右侧抽屉，支持概览、跟进记录、关联信息锚点，保存后保持列表上下文。

### 渠道商单

- 新增、状态更新、删除。
- 关联客户和可商务合作达人。
- 平台、内容类型、金额、佣金、发布日期、播放量。
- 状态、平台、内容类型筛选和关键词搜索。
- 预计发布日期列和人民币输入/展示。

### 朋友圈运营

- 发布计划新增、状态更新、删除。
- 周 mini 日历、日历/列表视图。
- 发布日期、内容、受众、预期转化、实际结果。
- 复盘回填、关联商机、来源自动追加到商机备注。

### 活动招商与公众号分析

- 读取共享活动招商，查看赞助方、金额和阶段，商务可更新跟进阶段。
- 公众号文章搜索、账号筛选、指标卡、文章分析笔记。
- 文章爆款状态由服务端按账号平均阅读量计算，客户端不能伪造。

## 六、市场工作台

### 活动运营

- 活动新增、搜索、软删除。
- 活动六 Tab：概览、任务看板、招商跟进、报名管理、财务复盘、进度总览。
- 新活动自动生成 P0-P4 阶段和财务模板。
- 任务拖拽、阶段完成度、报名、招商、物料和财务聚合。
- 双时区活动日历和北京时间显示。

### 场地资源库

- 场地新增、编辑、软删除、详情。
- 名称、标签、城市、类型、人数筛选。
- 最多 10 张照片、封面、轮播、踩点记录、历史活动。
- 根据城市、人数和类型快速匹配。

### 模板、物料和财务

- 文案模板新增、预览、变量替换、套用计数。
- 活动物料上传、类型和设计状态。
- 收入/支出录入、利润和利润率。
- CSV 明细导出、Markdown 复盘报告导出。
- 金额统一人民币元输入和展示，数据库保持最小货币单位整数。

### 仍需完善

- 竞品监测接入真实账号动态、内容变化和趋势时间线。
- 投放概览接入真实投放数据、成本、转化和归因。
- 活动物料与设计需求自动关联。
- 活动情报和每日流量话题接入市场摘要。

## 七、设计工作台

- 素材提交审核，boss 通过或驳回。

- 设计需求：提交、接单、制作中、已交付、退回修改。
- 视觉参考和交付记录。
- 设计任务四列看板：待设计、进行中、待审核、已完成。
- 品牌规范静态页和实时资产统计。

### 仍需完善

- 交付文件版本对比、版本回退和差异说明。
- 品牌规范数据化：颜色、字体、尺寸、禁用规则和检查结果。

## 八、剪辑工作台

### 已具备功能

- 微信视频号选题 CRUD。
- 三个预置账号、视频类型管理。
- 关键词、账号、类型、日期、标签、爆款状态筛选。
- CSV 模板下载、批量导入、筛选结果导出。
- 导入历史、指标快照和 SQL 分析视图。
- 服务端自动判定爆款：完播率不低于 60%，或播放量达到账号均值 2 倍。
- 对标账号、对标视频、分析笔记、风格分析。
- 热点话题解析和一键预填为选题。
- 选题、研究、视频任务、成片归档等核心表已接入 Supabase-first。

### 仍需完善

- 视频任务完整 CRUD 和负责人/截止日工作流进一步收口。
- 成片上传、预览、版本管理和文件权限验收。
- 发布排期、平台状态和发布结果回填。
- 每日情报自动生成内容选题、标签、音乐和视频结构建议。

## 九、跨工作台核心流程

### 设计审批

设计上传素材 → 提交审核 → boss 通过/驳回 → 通知设计师 → 设计需求引用已审批素材 → 交付 → boss/business 验收。

### 活动运营

市场建活动 → 自动生成阶段和财务模板 → 录入任务/场地/报名/招商/物料 → 拖拽推进 → 录入收支 → 导出复盘。

### 商务成交

新增客户 → 创建商机 → Pipeline 推进 → 选择可商务达人 → 创建渠道商单 → 发布/回填结果 → 形成经营数据。

### 剪辑生产

手动或 CSV 录入选题 → 服务端去重和爆款重算 → 调研热点/对标账号 → 生成视频任务 → 成片归档 → 发布排期。

### 团队记忆

任务和商机到期 → 通知负责人 → 日报/周报聚合 → 失败案例沉淀 → 总览展示团队记忆和自动化指标。

## 十、当前主要改进项

### P0：上线安全与真实环境闭环

1. 关闭公开注册，切换为邀请或管理员创建成员。
2. 清理测试账号、占位邮箱和本地测试数据。
3. 完成五角色权限矩阵的真实远程验证。
4. 验证 Storage 文件、签名 URL、图片/视频权限和失败行为。
5. 完成 Supabase 远程 migration、Secrets、飞书回调和 Edge Function 部署。
6. 加入错误监控、日志告警、备份恢复和回滚演练的实际执行记录。

### P1：工作台级每日情报中心

这不是市场专属功能，而是全局统一情报池：

- 总览：每日重点、风险、待处理事项。
- 市场：流量话题、类目趋势、竞品和活动动态。
- 商务：客户行业动态、品牌合作机会、商机相关事件。
- 设计：视觉风格、广告素材、包装和商品呈现趋势。
- 剪辑：热点选题、音乐、标签、爆款结构。
- 运营：平台规则、活动、物流和履约变化。

建议链路：

`来源适配器 → 抓取记录 → 去重归一化 → 主题/工作台分类 → 热度与可信度 → 摘要 → 收藏/已读/分派 → 转任务`

第一期必须保留来源、原文链接、抓取时间、地区、语言、主题、可信度和去重键。没有公开 API 的来源不能直接宣称自动抓取，应通过 RSS、官方页面、授权数据源或人工/CSV 导入适配。

### P1：补齐生产闭环

- 剪辑：视频任务、成片上传预览、发布排期。
- 设计：交付版本对比、品牌规范数据化、物料自动关联。
- 市场：真实投放数据、竞品变化和活动复盘对比。
- 总览：指标筛选、汇率口径、异常解释和跨工作台统一待办。

### P2：提升工作效率

- 所有长页面统一客户端锚点导航。
- 层级选择统一使用 Cascader。
- 日期、日期范围和时间统一使用 DatePicker，允许按业务场景配置未来日期。
- 手机端所有侧栏统一汉堡菜单 + Sheet 抽屉。
- 业务列表统一搜索、筛选、批量操作和结果计数工具栏。
- 详情页统一右侧抽屉、保存反馈和关联对象跳转。
- 将“空数据”统一改为可执行的下一步引导。

### P3：长期质量建设

- 加入 Playwright 多角色权限回归矩阵。
- 增加桌面、手机和 PWA 视觉截图回归。
- 为每日情报建立来源健康度、抓取成功率、去重率和人工采纳率指标。
- 对关键工作流加入审计事件、耗时和失败原因追踪。
- 建立产品指标：日活角色数、任务按期率、商机转化率、审批时长、内容选题采纳率。

## 十一、推荐实施顺序

1. 先完成远程安全收口和真实数据验收，避免在未稳定权限的数据基础上继续扩功能。
2. 接着完成每日情报中心的数据模型、来源适配器和统一前端入口。
3. 然后补齐剪辑发布闭环、设计版本管理和市场真实投放数据。
4. 最后做跨工作台效率统一、指标体系和视觉回归。

## 十二、结论

TK观察工作台已经从“多页面骨架”进入“多角色协作系统收口”阶段。核心 CRUD、审批、活动运营、商务 Pipeline、内容研究、通知、自动化、Supabase-first 迁移和 PWA 外壳已经形成基础闭环。

下一阶段重点不应继续堆叠装饰，而应集中在三件事：

1. 真实远程环境的安全、数据和文件验收。
2. 工作台级每日情报中心，把外部变化转成各角色可执行事项。
3. 补齐视频发布、设计版本、投放数据和总览决策能力。
