# 模块模板说明

“达人管理”是项目的标准 CRUD 参考实现。新增任何 `XX 管理` 时，复制它的结构和数据流，不跨 feature 引用内部组件。

## 标准数据流

```text
路由 URL query
  → 列表组件 CreatorTable
  → useCreators(params)
  → TanStack Query cache
  → PocketBase SDK / realtime subscription

表单 CreatorForm
  → react-hook-form + zod
  → create/update mutation
  → invalidate creators query
  → realtime 同步其他在线客户端
```

## 复制步骤

以“在商务工作台新增合同管理”为例：

1. 在 `features/business/types.ts` 增加 `Contract`、`ContractInput` 和 `ContractListParams`。
2. 在 `features/business/constants.ts` 增加合同状态、站点等稳定枚举。
3. 新建 `backend/pb_migrations/{timestamp}_create_contracts.js`，注释字段用途并设置 `boss/business` API Rules。
4. 复制 `hooks/use-creators.ts` 为 `hooks/use-contracts.ts`，修改 query key、collection、过滤字段和 mapper。
5. 分别复制详情、新增、更新、删除 mutation；不要把所有 mutation 塞进一个文件。
6. 复制 `creator-form.tsx`，先改 zod schema，再改表单字段和默认值。
7. 复制 `creator-table.tsx`，保留标题/筛选/表格/分页/更新时间的顺序。
8. 复制 `creator-detail.tsx`，确保详情和编辑使用同一领域类型。
9. 在 `routes/_app/business` 增加路由或在商务 Tabs 增加入口，并写三行权限注释。
10. 在 `features/business/index.ts` 只导出外部需要的入口。

## 必须保留的能力

- 300ms debounce 输入即搜。
- 状态、站点和业务必要筛选器可组合。
- 排序、页码和关键词同步 URL query。
- PocketBase realtime 事件使对应 query 失效。
- 表单编辑预填，zod 在提交前拦截非法数据。
- 单条和批量删除均二次确认。
- 批量状态更新。
- 列表显示最近数据更新时间。
- PocketBase 错误转换为中文 toast。
- mutation 成功后写非阻断审计记录。
- Collection API Rules 与前端角色守卫同步。

## 禁止事项

- 不从一个 feature import 另一个 feature 的内部文件。
- 不在组件中散落 PocketBase 字段名转换；统一放 mapper。
- 不用浮点金额；保存最小货币单位整数。
- 不直接修改已经部署过的 migration。
- 不用 `any`、`@ts-ignore` 或控制台打印认证数据。
- 不把搜索条件仅存在组件 state，导致链接无法复现。

## 验收清单

1. 目标角色和 boss 能列表、新增、查看、编辑、删除。
2. 无权限角色直接访问 API 不能读取真实数据，写入被拒绝。
3. 两个浏览器同时打开，任一端修改后另一端无需刷新即更新。
4. 搜索、筛选、排序和翻页后 URL 可复制复现。
5. PocketBase 停止时页面显示中文网络错误，不白屏、不无限加载。
6. `pnpm typecheck`、`pnpm lint`、`pnpm --dir apps/web format:check` 和 `pnpm build` 全部通过。
