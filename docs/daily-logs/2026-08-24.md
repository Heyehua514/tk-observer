- 自我攻击：新增双账号 RLS 回归。账号 B 无法读取账号 A 的个人记忆、无法改变 A 的记忆值，也不能伪造 A 的 `owner_id` 建立记忆；测试事务自动回滚。
- 发现并修复 Realtime 审计漂移：`ai_memory` 已由 migration 发布到 `supabase_realtime`，但白名单测试未登记，现已显式纳入，防止后续新增实时表绕过清单审计。

### 反思

- 数据库门禁失败先单跑最小 SQL 文件，可以把 migration 状态、pgTAP 兼容性和测试计数问题拆开定位，避免在 554 条测试输出中浪费排查时间。

## AI 建议人工决策闭环

- 追加 `20260824000100_ai_notes_decisions.sql`：`ai_notes` 新增 `decision`（`pending` / `adopted` / `dismissed`）和 `decided_at`。数据库约束要求待决策记录没有决策时间，最终状态必须带决策时间；新增按成员、状态、时间的活跃记录索引。
- AI 记录库显示待决策、已采用或已忽略。只有当前记录所有者可对 Supabase 记录操作「采用」或「忽略」；点击后仅更新决策字段并写入非阻断审计，不自动创建或修改任务、负责人、金额、截止日期、商机或其他业务数据。PocketBase 显式回退保持只读历史记录行为。
- 自我攻击：非 owner 对他人记录的决策更新被 RLS 过滤，攻击后原记录仍为待决策；非法将 `adopted` 与空决策时间写入被数据库拒绝。
- 验证：新增 UI gate 1 条、Supabase gate 10 条、Supabase eval 3 条。全量 `pnpm supabase:schema:test` 2/2、`pnpm supabase:test` 39 文件 / 567 断言、`pnpm typecheck`、`pnpm lint`、前端 143 文件 / 325 测试、`pnpm build`、`git diff --check` 全部通过。本机 migration 已应用，未写远程 Supabase。

### 反思

- AI 结果是否采用是显式状态机，不应依靠空备注或审计文本推断。将状态和时间放在同一条记录上能让后续个人记忆学习读取明确的人类选择，同时不扩张为自动执行能力。
- 负责人能查看成员记录，但不能代替成员采用或忽略。前端按照 owner 隐藏按钮，数据库 RLS 再次限制越权更新，两个边界共同防止误操作。
