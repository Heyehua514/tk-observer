## WorkBuddy 网关客户端自启动

- 将本机网关从硬编码 Node + LaunchAgent 改为 Tauri 内置 Rust 服务。打开客户端自动启动，端口冲突时每 2 秒重试，客户端退出后不残留新的后台进程。
- 新版首次启动停用旧 `com.tkobserver.workbuddy-gateway` 登录项并保留 plist 备份，避免旧 Node 服务长期占用 8877。
- 安全复核后补齐单任务执行锁：同一时间只运行一个 WorkBuddy CLI，忙时返回 `429 GATEWAY_BUSY`；Rust 与旧 Node 兼容入口都限制 1 MiB 请求体、8 MiB CLI 输出和 120 秒执行时长，不再回传原始 CLI JSON。
- 浏览器调用增加 125 秒终止等待，旧网关或异常连接不再让 AI 按钮永久停留在执行中。
- 增加来源白名单、1 MiB 请求上限、8 MiB 输出上限、120 秒 CLI 超时、Private Network Access 预检和非敏感错误码。
- 前端恢复提示改为打开桌面客户端并确认 WorkBuddy 已登录，不再让普通用户双击脚本。
- Gate/eval 当前覆盖 11 条 Rust 网关测试、8 条旧 Node 网关测试和 5 条前端/评测用例；真实冒烟验证 200/204/403/400 状态和 Rust 进程接管端口，未消耗 WorkBuddy 额度。

## 反思

- 自动启动不能只看 `RunAtLoad`，还要验证分发后的运行时和路径是否存在。功能属于客户端生命周期时，应由客户端进程拥有，而不是依赖源代码目录。
- 公网 HTTPS 调本机 loopback 需要同时考虑普通 CORS 和浏览器 Private Network Access；只返回 `Access-Control-Allow-Origin: *` 不能作为长期兼容方案。
