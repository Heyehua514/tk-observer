# 2026-09-17 每日记录

## AI 功能跨端与 Windows 本地 WorkBuddy 网关适配修复

- **排查根因**：
  1. 在其他电脑或纯浏览器环境打开时，未启动本地网关且前端无法跨设备连接 127.0.0.1，此前未在前端提供直观的网关配置与连通性检测能力。
  2. 桌面/脚本网关原先默认写死 macOS CLI 路径，在 Windows 下直接触发 `ENOENT`；Windows 环境下的 Node CLI 为 JS 脚本（无 `.exe` 后缀），直接通过 `execFile` 调用会失败，必须由 `node.exe` 引导启动。
- **改动与实现**：
  1. `scripts/workbuddy-gateway/server.mjs`：增加跨平台 CLI 探测（优先检测环境变量 `CODEBUDDY_CLI` / `WORKBUDDY_CLI`，探测 Windows `C:\Program Files\WorkBuddy` 与 `%LOCALAPPDATA%` 路径，回退至 macOS 路径）；实现 `resolveCliExecution`，在 Windows 非 `.exe` 路径下自动通过 `process.execPath` 引导执行。
  2. `scripts/workbuddy-gateway/start.bat`：新增 Windows 一键启动脚本，便于无桌面 Rust 环境下快速启动本地网关。
  3. `apps/web/src/features/shared-ai/workbuddy-gateway.ts`：增加网关配置存取与响应检测方法 `getStoredGatewayUrl`、`setStoredGatewayUrl`、`checkGatewayStatus`。
  4. `apps/web/src/features/settings/server-settings.tsx`：在「服务设置」中增加 WorkBuddy AI 网关配置卡片，支持自定义远端/本地网关 URL、一键连通性测试以及恢复默认，彻底解决其他电脑或局域网设备接入问题。
  5. `apps/web/src/features/shared-ai/workbuddy-gateway.test.ts` & `scripts/workbuddy-gateway/gateway.test.mjs`：补齐配置存取与 Windows CLI 命令封装自动化测试。
