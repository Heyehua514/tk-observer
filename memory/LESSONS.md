# 项目错题本与经验库 (LESSONS)

> 规则说明：每次任务中踩坑、类型检查报错或重构事故，在此追加一条具体规避规则。保持精简，定期合并。

1. **后端优先**：涉及全栈功能时，先写 Supabase Migration 并校验，严禁先写前端假数据导致返工。
2. **三击熔断**：任何单一编译/运行错误连续尝试 3 次未果，立即记录现场并挂起，转入下一任务，严禁死磕。
3. **确定性脚本**：涉及数据处理与迁移，写独立脚本跑完即走，严禁在模型上下文手工处理大批量数据。
4. **跨币种一致性**：涉及多国家/多币种定价与成本时，必须显式定义采购成本币种、销售币种与基准汇率转换函数，严禁在未换算汇率的情况下直接做减法计算毛利率与利润。
5. **跨模块流转闭环**：跨模块数据流转（如雷达转选品）必须依据源端真实数据加权换算而非随意填充假数据，且必须回写源实体流转标记，形成完整的生命周期溯源链条。
6. **双写同步与持久化闭环**：当新增从属事件明细（如达人触达跟进日志、商机阶段变更）并关联主实体状态（如最近联系时间、合作状态）时，必须在数据库层通过触发器自动回写主表，并在应用服务层执行即时同步与缓存联动刷新，杜绝明细已创建而主表状态滞后的脱节隐患。
7. **度量指标安全换算与展示兜底**：涉及转化金额与互动率等核心表现指标时，数据库层必须按最小货币单位整数（如分/cents）持久化防浮点误差，前端模型层必须提供显式分到元格式化工具与分母为零的安全兜底函数，并在测试中覆盖零值与负值边界。
8. **多实体级联流转与双向回写防御**：当实体之间存在上下游流水线依赖（如任务流转完成 ➔ 自动入排期、成片归档 ➔ 反向回写任务完成并绑定排期外键）时，数据库触发器应保持幂等（检查 not exists 防重复创建，并仅补全缺失外键），服务层必须显式批量使下游所有受影响缓存键（如任务列表、排期列表、成片列表）失效，杜绝只刷新当前实体而导致关联视图不同步的问题。
9. **RLS软删除解耦与权限闭环**：在 PostgreSQL RLS 架构下，任何支持软删除（`update deleted_at = ...`）的业务表，其 `SELECT` 策略必须纯粹按角色权限矩阵或属主收口，严禁在 `SELECT` 策略中拼接 `deleted_at is null` 条件（否则非 owner 角色执行软删除更新时，PostgreSQL 评估新行可见性会直接触发 RLS 403 `new row violates policy`）；软删除业务隔离统一由客户端数据层显式追加 `.is('deleted_at', null)` 过滤。同时，新建表必须补充 PostgREST 全局权限与静态审计测试，杜绝权限悬空。
10. **跨域全链路编排与契约防御**：跨多个独立业务域（如雷达选品、达人CRM、剪辑任务与排期数据打卡）进行流转协作时，必须建立统一的生命周期编排器（Orchestrator）与契约验证函数，明确校验上下游依赖的合法性（如达人合作意向校验、状态机流转守卫与除零边界兜底），杜绝跨模块随意拼凑字段或跳过状态约束导致的数据孤岛与脏数据。
11. **剪辑工程与时间基准规范**：在与外部音视频剪辑工程（如剪映电脑版 JianyingPro）对接生成草稿配置（`draft_content.json`）时，时间轴必须统一使用整数微秒（1s = 1,000,000μs）对齐各轨道，且必须显式区分素材原始区间（`source_timerange`）与画布播放区间（`target_timerange`），杜绝浮点秒误差导致的声音画面错位与草稿解析损坏。
12. **AI复盘记忆与容错持久化契约**：在引入 AI 智能切片、风格反思与踩坑复盘回流到系统表（如 `ai_memory`、`failed_cases`）时，数据库 CHECK 约束必须前置纳管新场景枚举与文本长度限制，服务层必须封装支持降级回退的确定性持久化函数，并在落库异常时通过日志兜底，严禁因复盘记忆写入失败中断前台业务主流程。
13. **跨域全链路流转与实况聚合防御**：在构建横跨多业务域（雷达、选品、达人、剪辑、排期）的全局流水线与驾驶舱监控时，业务流转逻辑（如雷达转选品）必须严格复用编排器（Orchestrator）契约函数与字段安全换算，严禁在各工作台 Hook 中各自分散裸写临时算式；同时全局聚合 Hook（如跨工作台待办、链路健康度）必须对多表查询提供并发容错与空态降级兜底，组件层保持 props 注入与实时拉取双模式，确保单元测试隔离与线上真实监控无缝解耦。
14. **用户偏好设置必须闭环消费**：任何在设置页暴露给用户的开关或偏好（如通知静音、提醒类别），必须在数据服务与 UI 展示层显式接入过滤口径，严禁只写库不读取导致“设置了却不生效”的假配置；偏好缺失或加载失败时必须以安全默认值降级放行，不得阻断主流程。
15. **全局检索与工作台路由参数闭环**：跨业务域全局搜索向目标工作台（达人、客户、选品、竞品与成片）下钻时，必须通过统一纯契约导航函数（如 `buildWorkbenchNavigation`）完整带入真实搜索词与定位参数，严禁在跳转路径中硬编码空字符串 `query: ''` 导致用户丢失上下文；同时底层检索必须在数据库层挂载 `count: 'exact'` 返回真实总条数并配置特定类型过滤，杜绝因分页 limit 导致总数显示失真的假数据隐患。
16. **权限单一契约与清理一致性**：前端权限矩阵必须由单一契约统一消费，路由守卫与侧边栏不得各自手写角色表；权限回归测试应独立断言矩阵，退出、401 与切换服务器必须共用同一缓存清理函数。

17. **派生字段夹具必须完整**：ProductRow 等包含派生金额字段的模型，测试 Mock 必须补齐 profitInCnyMinor、priceInCnyMinor、costInCnyMinor、marginLevel，或直接复用 `buildProductRows` 构造数据；严禁只提供原始价格与成本字段后断言 UI 金额，避免 ¥NaN 假故障掩盖真实回归。

18. **邮箱邀请准入唯一授权**：Supabase 成员准入必须以 owner 创建的邮箱邀请为唯一授权来源，角色只能由邀请记录写入；注册端提交的姓名或角色不得参与权限判定，未匹配有效邀请的账号必须保持 pending 并拒绝登录。

19. **邀请状态机并发闭环**：邀请的 accepted 状态必须由数据库约束与触发器禁止回写，服务层保存/撤销必须携带旧状态条件并在更新 0 行时 fail-closed；前端操作动作必须消费同一纯函数契约，严禁各组件自行判断状态或仅靠页面刷新防并发漂移。

20. **批量导入原子性与可逆审计**：CSV 批量导入必须由数据库 RPC 在单事务内完成业务写入、历史落库与逐行前后快照，严禁客户端循环写业务表或直接伪造导入历史；整批撤销必须先验证全部记录未被后续修改，并在冲突时 fail-closed。
